# RAG Assignment: Baseline vs. Cross-Encoder Re-Ranking

## Overview

This project compares two Retrieval-Augmented Generation (RAG) pipelines using the **NIST AI Risk Management Framework (AI RMF 1.0)** as the source document.

The objective is to investigate whether Cross-Encoder re-ranking improves the relevance of retrieved passages and the quality of answers generated by a language model.

## Objectives

- Implement a baseline RAG pipeline using dense retrieval.
- Implement a two-stage retrieval pipeline with Cross-Encoder re-ranking.
- Compare retrieved chunks and generated answers for selected queries.
- Analyze rank shifts and cases where relevant evidence is missed by baseline retrieval.
- Measure retrieval and re-ranking latency.

## Dataset

**Document:** NIST AI Risk Management Framework (AI RMF 1.0)

The PDF text was extracted using PyMuPDF and divided into **154 overlapping chunks**, each approximately 900 characters long with a 150-character overlap. Both pipelines use the same chunk collection.

## Models and Technologies

| Component | Model or Tool |
|---|---|
| PDF text extraction | PyMuPDF |
| Bi-Encoder | `sentence-transformers/all-MiniLM-L6-v2` |
| Cross-Encoder | `cross-encoder/ms-marco-MiniLM-L-6-v2` |
| Answer generation | `Qwen/Qwen2.5-1.5B-Instruct` |
| Embedding similarity | Cosine similarity |
| Framework | Python, Hugging Face Transformers, Sentence Transformers |

## Methodology

### 1. Baseline RAG

1. Encode the query using the Bi-Encoder.
2. Retrieve the top 10 chunks using cosine similarity.
3. Select the top 3 chunks.
4. Generate an answer using the selected context.

### 2. Re-Ranked RAG

1. Retrieve the same top 10 candidates using the Bi-Encoder.
2. Score the query–chunk pairs using the Cross-Encoder.
3. Reorder the candidates according to their Cross-Encoder scores.
4. Select the top 3 re-ranked chunks.
5. Generate an answer using the selected context.

Both pipelines use the same answer-generation model and prompt structure.

## Experimental Results

Three retrieval and re-ranking latency runs produced the following averages:

| Operation | Average Latency |
|---|---:|
| Bi-Encoder retrieval (top 10) | 11.9 ms |
| Cross-Encoder re-ranking (10 candidates) | 36.3 ms |
| Combined retrieval and re-ranking | 48.2 ms |

These measurements exclude answer generation. The results indicate that re-ranking adds a small absolute latency cost in the tested environment, while potentially improving the relevance of the context supplied to the language model.

The notebook also analyzes queries involving unmeasurable AI risks, responses to systems that no longer perform as intended, and procedures for previously unknown AI risks.




This project demonstrates a two-stage RAG approach in which a Bi-Encoder efficiently retrieves candidate passages and a Cross-Encoder re-ranks them for more detailed relevance assessment. The experiments illustrate how re-ranking can improve evidence selection for some queries, while also showing the importance of evaluating the completeness and grounding of the final generated answers.
